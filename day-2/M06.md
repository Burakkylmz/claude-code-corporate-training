# M06 — Controlled Implementation & Human Review

## Learning Goal

Gerçek bir engineering ticket'ını Claude Code ile önce kapsamlı bir implementation plan'a dönüştürmek; human gate sonrasında planı bounded şekilde execute etmek ve task'i test + diff + human review evidence'ı ile kapatmak.

## Key Idea

```text
Engineering Ticket
→ Extensive Plan
→ Human Gate
→ Execute
→ Targeted Verification
→ Diff
→ Human Review
→ Task Closure
```

---

## D02-M06-P01 — Task Brief: CRM Timeout Fallback

### Mode

```text
Plan Mode
```

### Prompt

```text
Engineering Ticket: CC-201 — CRM Timeout Fallback

Repository:
call-center-integration-platform

Business requirement:

CRM customer lookup sırasında CrmTimeoutException oluşursa incoming call
hemen fail olmamalı. Existing call orchestration ve IVR abstraction'ı
kullanılarak kontrollü fallback uygulanmalı.

Required behavior:

- successful CRM flow değişmemeli
- yalnız CRM timeout scenario fallback üretmeli
- non-timeout CRM failures mevcut behavior'ını korumalı
- existing public/external contracts gereksiz yere değişmemeli
- retry veya circuit-breaker eklenmemeli
- unrelated refactor yapılmamalı

Day 1'de repository architecture'ı zaten keşfettik.
Repository-wide exploration yapma.
Yalnız bu ticket için gerekli code/test/config surface'i oku.

Henüz implementation yapma.

Önce extensive bir implementation plan üret.

Plan şu bölümleri içersin:

## 1. Current Behavior
- relevant runtime flow
- exact entry point / orchestration method
- CRM boundary
- current failure propagation

## 2. Acceptance Criteria
- observable success criteria
- unchanged behavior
- explicit non-goals

## 3. Change Surface
- exact production files
- exact test files
- config impact varsa belirt
- her file için neden değişmesi gerektiğini açıkla

## 4. Implementation Steps
- ordered steps
- her step'in dependency'si
- her step'in expected outcome'u

## 5. Test Plan
- happy path
- CRM timeout path
- non-timeout CRM failure
- relevant regression scenarios

## 6. Verification Plan
- exact commands
- targeted tests
- relevant broader verification
- git diff review

## 7. Risks / Unknowns
- architecture uncertainty
- exception semantics risk
- scope-creep risk
- unsupported assumptions

## 8. Stop Conditions
Implementation sırasında hangi durumda durup human decision istemen gerektiğini yaz.

Son olarak planı şu status ile bitir:

READY FOR HUMAN REVIEW
veya
BLOCKED BY MISSING EVIDENCE

File değiştirme.
Test/build çalıştırma.
Git mutation yapma.
```

### What to Observe

- Claude repository'yi tekrar baştan keşfediyor mu, yoksa task-focused mı ilerliyor?
- Plan yalnız file listesi mi, yoksa behavior + order + verification içeriyor mu?
- Non-timeout behavior explicit olarak korunuyor mu?
- Exact files/symbols evidence ile gösteriliyor mu?
- Unknown bir noktada uydurmak yerine block ediyor mu?

### Discussion Point

> **Plan, yapılacak işlerin listesi değil; execution'ın technical contract'ıdır.**

## D02-M06-P02 — Human Gate: Freeze the Execution Contract

### Mode

```text
Plan Mode
```

### Prompt

```text
CC-201 implementation planını henüz execute etme.

Planı human review için son kez normalize et.

Yalnızca şu çıktıyı ver:

1. Files to modify
2. Files explicitly not to modify
3. Ordered implementation steps
4. Acceptance criteria
5. Verification commands
6. Main risks
7. Stop conditions

Ayrıca planın requirement dışında gereksiz değişiklik içerip içermediğini critique et.
Varsa çıkar.

Son satır:
AWAITING HUMAN APPROVAL

File değiştirme.
```

### What to Observe

- Human approval öncesinde scope freeze ediliyor mu?
- Plan gereksiz abstraction/refactor içeriyorsa daraltılıyor mu?
- Execution başlamadan verification yolu belirli mi?

### Discussion Point

```text
Plan produced
≠
Plan approved
```

## D02-M06-P03 — Execute the Approved Plan

### Mode

```text
Default / Edit-capable Mode
```

### Prompt

```text
Human approval:

CC-201 için bir önceki mesajdaki execution contract onaylandı.
Approved planı execute et.

Rules:

- yalnız approved files üzerinde çalış
- approved order'ı takip et
- successful CRM flow'u değiştirme
- yalnız CrmTimeoutException fallback üretmeli
- non-timeout CRM failures mevcut semantics ile propagate etmeli
- existing IVR/domain abstraction'ı reuse et
- public/external contract'ı requirement gerektirmedikçe değiştirme
- dependency ekleme
- retry/circuit-breaker ekleme
- unrelated cleanup/refactor yapma
- commit/push yapma

Her implementation step'inden sonra kısa olarak:
- changed file
- fulfilled acceptance criterion
- unexpected issue

raporla.

Approved plan ile repository reality arasında kritik conflict görürsen STOP.
Kendin yeni architecture kararı verme.

Implementation bittikten sonra hemen task'i complete ilan etme.
Verification aşamasına geçmek için kısa implementation summary ver.
```

### What to Observe

- Agent planı gerçekten execution boundary olarak kullanıyor mu?
- Unexpected issue çıktığında scope'u kendiliğinden genişletiyor mu?
- Implementation sırasında unrelated refactor oluşuyor mu?
- Plan ile diff arasındaki traceability korunuyor mu?

### Discussion Point

> **Human approval sınırsız yetki değildir; approved planın execute edilmesine verilen bounded izindir.**

## D02-M06-P04 — Verify Before “Done”

### Prompt

```text
CC-201 implementation tamamlandı.

Şimdi completion claim yapmadan önce verification çalıştır.

Sıra:

1. targeted tests
2. ticket ile ilişkili relevant regression tests
3. gerekli ise compile/build verification
4. git status
5. git diff

Network veya external service kullanma.
Commit/push yapma.

Her command için:
- exact command
- exit/result
- tests run
- failures/errors
- hangi acceptance criterion'u kanıtladığı

raporla.

Bir verification failure varsa task'i COMPLETE ilan etme.
Failure'ı olduğu gibi raporla ve dur.
```

### What to Observe

- “Code yazıldı” ile “task bitti” ayrılıyor mu?
- Test evidence acceptance criteria ile eşleştiriliyor mu?
- Failure olursa Claude sonucu saklamadan task'i incomplete bırakıyor mu?

### Discussion Point

```text
Implementation complete
≠
Engineering task complete
```

## D02-M06-P05 — Human Diff Review & Task Closure

### Prompt

```text
CC-201 için implementation ve verification tamamlandı.

Şimdi current git diff'i human review'a hazırlamak için incele.
Yeni edit yapma.

Review criteria:

- approved change surface dışına çıkılmış mı?
- acceptance criteria gerçekten karşılanıyor mu?
- successful CRM behavior korunmuş mu?
- non-timeout failure semantics korunmuş mu?
- integration boundary doğru mu?
- tests behavior'ı gerçekten kanıtlıyor mu?
- assertion weakening var mı?
- unnecessary complexity/refactor var mı?
- unexpected dependency/config change var mı?

Çıktı formatı:

## Changed Files

## Acceptance Criteria Status
Her criterion için:
- PASS
- CONCERN
- FAIL

## Verification Evidence

## Diff Review Findings

## Remaining Risks / Assumptions

## Final Recommendation
Yalnız birini seç:
- ACCEPT
- REVISE
- REVERT

Human reviewer final kararı vermeden commit/push yapma.
```

### What to Observe

- Claude kendi yaptığı code'u eleştirebiliyor mu?
- Summary yerine actual diff evidence kullanılıyor mu?
- “Tests green” tek başına ACCEPT sebebi yapılıyor mu?
- Final acceptance human'da kalıyor mu?

### Discussion Point

> **Claude “done” diyebilir; engineering task ancak evidence + diff + human acceptance ile kapanır.**

---

## Task Closure Standard

```text
CC-201 CLOSED only if:

[ ] Acceptance criteria met
[ ] Targeted tests pass
[ ] Relevant regression passes
[ ] Changed files reviewed
[ ] git diff reviewed
[ ] No unexpected scope
[ ] Remaining risks documented
[ ] Human decision = ACCEPT
```

---

## Module Takeaway

```text
Plan deeply.
Execute narrowly.
Verify explicitly.
Review the diff.
Close with evidence.
```
