# M15 — Sustainability, Vendor Independence & Team Cost Governance

## Learning Goal

Agentic workflow'u model/vendor bağımlılığını azaltacak, team cost'u görünür kılacak ve organizational knowledge'i kalıcı hale getirecek şekilde tasarlamak.

## Key Idea

```text
Externalize
→ Version
→ Measure
→ Optimize
→ Preserve
```

---

## D03-M15-P01 — Find Vendor-Coupled Knowledge

### Mode

```text
Plan Mode
```

### Prompt

```text
Repository ve training workflow'unda knowledge'in nerede yaşadığını değerlendir.

Şu kategorileri ayır:

- repository-owned knowledge
- Claude-specific configuration
- prompt-only knowledge
- transient conversation context
- tool/vendor-specific behavior
- portable engineering standards

Amaç vendor migration yapmak değil.

Şunları belirle:

1. Hangi knowledge yalnız chat/session içinde kaybolabilir?
2. Hangisi repository docs/rules içine taşınmalı?
3. Hangi standards vendor-independent ifade edilebilir?
4. Hangi parçalar Claude Code'a özgü kalmak zorunda?
5. Vendor değişirse hangi engineering knowledge korunur?

Henüz file değiştirme.
```

### Discussion Point

> **Sustainable operating model, organizational knowledge'i tek modelin hafızasına bırakmaz.**

---

## D03-M15-P02 — Cost Governance Review

### Prompt

```text
Mevcut Claude Code workflow'unu usage/cost açısından değerlendir.

Evidence olarak mümkünse:

- /context
- /usage
- subagent usage
- large-context sessions
- model choice
- tool-call patterns

gibi local observations'ı kullan.

Şu başlıklarda öneri üret:

- scope control
- context hygiene
- subagent policy
- model escalation policy
- verification proportionality
- repeated task automation
- team-level measurement

"Her zaman en ucuz modeli kullan" veya
"her zaman en güçlü modeli kullan" gibi blanket rule üretme.
```

### Discussion Point

```text
Cost governance
≠
model downgrading

Cost governance
=
right work
+ right context
+ right tool
+ right model
+ right evidence
```

## D03-M15-P04 — Session Knowledge → Project State

### Prompt

```text
Mevcut session'da yalnız conversation içinde kalan bilgileri sınıflandır:

- transient exploration
- task evidence
- project knowledge
- organizational policy

Kalıcı olması gereken bir finding varsa bunun doğru destination'ını öner:

- source code
- test
- contract
- README
- ADR
- runbook
- project rule

Her conversation finding'i dokümana taşımaya çalışma.
Yalnız kalıcı ve yeniden keşfi maliyetli bilgileri externalize etmeyi öner.

Henüz file değiştirme.
```

### Discussion Point

```text
Chat history
→ working area

Repository artifacts
→ canonical project knowledge
```
