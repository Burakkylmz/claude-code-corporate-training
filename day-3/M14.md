# M14 — Team Standards & Multi-Developer Operating Model

## Learning Goal

Claude Code kullanımını bireysel prompt alışkanlıklarından çıkarıp shared repository standards ve isolated work patterns ile ekip operating model'ine dönüştürmek.

## Key Idea

```text
Personal Preference
→ Shared Rule
→ Versioned Repository Knowledge
```

---

## D03-M14-P01 — Inspect Shared Standards

### Mode

```text
Plan Mode
```

### Prompt

```text
Repository'deki shared engineering instructions'ı incele:

- CLAUDE.md
- .claude/rules/*
- relevant docs

Şunları sınıflandır:

- architecture standards
- testing standards
- security/data standards
- Git governance
- local-only preference
- team-wide rule

Her rule için belirt:

- scope
- owner
- why it belongs in repository
- whether it is deterministic or judgment-based
- whether it should remain shared or become narrower scoped guidance

Henüz file değiştirme.
```

### Discussion Point

> **Organizational knowledge chat history'de değil, versioned repository context'inde yaşamalıdır.**

---

## D03-M14-P02 — Multi-Developer Work Isolation

### Prompt

```text
İki developer'ın aynı training repository üzerinde
iki bağımsız task çalıştığını varsay.

Amaç:
- değişikliklerin birbirini kirletmemesi,
- context ve Git state'in ayrılması,
- review boundary'nin korunması.

Bir operating model öner.

Şunları değerlendir:

- separate branches
- Git worktrees
- task ownership
- shared contracts
- contract freeze points
- merge order
- conflict handling
- human review responsibilities

Henüz branch/worktree oluşturma.
Sadece team workflow planı üret.
```

### Discussion Point

```text
Parallel people
→ isolated workspaces
→ shared contracts
→ controlled integration
```

---

## D03-M14-P03 — Team Rule Change Review

### Prompt

```text
Yeni bir team rule önerildiğini varsay:

"Her implementation sonrasında full test suite otomatik çalıştırılsın."

Bu rule'u hemen CLAUDE.md'ye ekleme.

Önce değerlendir:

- benefit
- cost
- false rigidity
- when targeted tests are enough
- when full suite is required
- whether rule should be guidance, hook, CI rule, or human decision

Sonuçta en uygun enforcement layer'ı öner.
```

### Discussion Point

> **Shared rule eklemek kolaydır; yanlış rule bütün ekibin maliyetini büyütür.**

---

## Module Takeaway

```text
Shared standards
+ isolated work
+ explicit ownership
→ scalable agentic engineering
```
