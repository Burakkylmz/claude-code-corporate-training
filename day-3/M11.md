# M11 — Git/GitHub Governance & Delivery Boundaries

## Learning Goal

Agent'ın local Git evidence üretmesi ile remote delivery action alması arasındaki governance sınırını netleştirmek.

## Key Idea

```text
Local Evidence
≠
Remote Authority
```

---

## D03-M11-P01 — Git State Inspection

### Mode

```text
Manual Mode
```

### Prompt

```text
Repository'nin mevcut Git state'ini yalnızca read-only olarak incele.

Allowed:

- git status
- git diff
- git diff --stat
- git log gibi read-only Git commands

Not allowed:

- git add
- git commit
- git push
- git pull
- git merge
- git rebase
- git reset
- git checkout/switch ile state mutation
- branch create/delete
- remote mutation

Şunları raporla:

1. Current branch
2. Working tree clean mi?
3. Modified/untracked files
4. Diff summary
5. Change'in logical boundary'si
6. Commit için hazır olup olmadığı konusunda evidence

Her command'ı çalıştırmadan önce göster ve manual approval iste.
```

### What to Observe

- Read-only Git actions ile mutation actions ayrılıyor mu?
- Agent remote action'a geçiyor mu?

### Discussion Point

> **Repository'yi okuyabilmek, delivery state'ini değiştirmeye yetkili olmak değildir.**

## D03-M11-P02 — Commit Boundary Planning

### Prompt

```text
Mevcut diff'i kullanarak atomic commit boundary öner.

Henüz git add veya git commit yapma.

Raporla:

- proposed commit purpose
- files included
- files excluded
- why this is atomic
- suggested commit message
- pre-commit verification required

Eğer diff içinde unrelated changes varsa ayrı commit öner ama otomatik split yapma.
```

### Discussion Point

```text
One commit
→ one coherent engineering reason
```

---

## D03-M11-P03 — Local Commit Gate

### Prompt

```text
Human approval verilmeden commit oluşturma.

Commit öncesi yalnızca şu checklist'i raporla:

- working tree state
- tests/evidence
- files included
- files excluded
- commit message
- remote actions explicitly prohibited

Sonra dur.
```

---

## Module Takeaway

```text
Inspect
→ Bound
→ Verify
→ Human Approval
→ Commit
```
