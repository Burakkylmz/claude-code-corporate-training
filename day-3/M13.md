# M13 — Hooks & Deterministic Enforcement

## Learning Goal

Tekrarlanan governance kontrollerini yalnız prompt discipline'e bırakmak yerine deterministic enforcement ile desteklemek.

## Key Idea

```text
Instruction
→ probabilistic guidance

Hook
→ deterministic enforcement point
```

---

## D03-M13-P01 — Find a Repeated Control

### Mode

```text
Plan Mode
```

### Prompt

```text
Bu training repository workflow'unda sürekli tekrar ettiğimiz kontrolleri incele.

Örnek kategoriler:

- test execution before delivery
- repository cleanliness
- forbidden command patterns
- secret / sensitive-data checks
- diff verification

Henüz hook yazma.

Şunları belirle:

1. Hangi control sürekli insan hatırlatmasına bağlı?
2. Hangisi deterministic bir hook için uygun?
3. Hangisi hook için uygun değil ve human judgment gerektiriyor?
4. Hook failure durumunda expected behavior ne olmalı?
5. False positive / false negative riskleri neler?

Bir tane high-value, low-ambiguity hook use case öner.
```

### Discussion Point

> **Her governance rule hook değildir; deterministic olanları automation'a taşı.**

---

## D03-M13-P02 — Design the Hook

### Prompt

```text
Seçilen use case için hook design üret.

Henüz file oluşturma.

Design şu alanları içersin:

- Trigger
- Input
- Deterministic check
- Pass behavior
- Fail behavior
- Exit code / signal
- Developer-visible message
- Bypass policy
- Security considerations
- Test strategy

Hook business logic çözmesin.
Yalnız enforcement yapsın.
```

### What to Observe

- Hook objective mi?
- Pass/fail deterministic mi?
- Human judgment gerektiren alan hook'a zorla taşınıyor mu?

## D03-M13-P03 — Implement One Bounded Hook

### Mode

```text
Manual Mode
```

### Prompt

```text
Human approval:

Yalnızca approved hook design'ını implement et.

Allowed:
- gerekli hook/config file edit
- hook'un local test'i

Not allowed:
- unrelated rules
- network
- dependency expansion unless explicitly approved
- Git commit/push
- automatic merge

Implementation sonrası:
- exact files changed
- hook trigger
- pass case
- fail case
- local verification evidence

raporla ve dur.
```

### Discussion Point

```text
Prompt says "please remember"
≠
System enforces it
```

## Module Takeaway

> **Deterministic controls, repeated human memory dependency'sini azaltır.**
