# M02 — Plan-first Development & Permissions

## Learning Goal

Implementation'dan önce exploration, explicit planning, human review ve approval gate kullanımını görmek.

## Key Idea

```text
Requirement
→ Explore
→ Plan
→ Human Review
→ Approval
→ Implement
→ Verify
```

> **Can do ≠ Allowed to do ≠ Approved to do**

## D01-M02-P01 — Request Validation Discovery

### Mode

```text
Plan Mode
```

### Prompt

```text
CallController request validation behavior'ını incele.

Henüz implementation planı oluşturma.

Şunları belirle:

1. Request model hangi validation annotation'larını kullanıyor?
2. Controller validation'ı nasıl tetikliyor?
3. Validation dependency mevcut mu?
4. Validation behavior için controller/HTTP-level test var mı?
5. Existing tests validation'ı gerçekten exercise ediyor mu?
6. Behavior'ın source code'da bulunması ile test tarafından korunması arasında gap var mı?
7. Bu behavior'ı doğrulamak için minimum relevant file set nedir?

Bu aşamada:
- file değiştirme,
- yeni test oluşturma,
- build/test çalıştırma,
- dependency değiştirme,
- Git işlemi yapma.

Sadece current-state discovery yap.
```

### What to Observe

- `@NotBlank`
- `@Valid @RequestBody`
- validation dependency
- controller/HTTP-level test coverage

### Discussion Point

> Source annotation'ın varlığı, behavior'ın regression test ile korunduğu anlamına gelmez.

## D01-M02-P02 — Explicit Plan & Permission Classification

### Prompt

```text
Önceki validation discovery sonucuna göre yalnızca bir implementation planı üret.

Henüz implementation yapma.

Plan şu bölümleri içersin:

- Goal
- Acceptance Criteria
- Minimum Change Surface
- Test Strategy
- Dependency Check
- Verification Plan
- Risk Assessment
- Permission Classification
- Explicit Non-Actions
- Open Questions
- Human Approval Gate

Permission classification için şu kategorileri kullan:

- READ
- WRITE
- EXECUTE
- EXTERNAL
- GIT LOCAL
- GIT REMOTE

Her action için:
- gerekli mi?
- risk seviyesi nedir?
- human approval gerekiyor mu?

Production code'da gereksiz temporary mutation önerme.

Eğer mevcut test infrastructure yeterli değilse dependency değişikliğini
otomatik olarak plan kapsamına alma.
Bunu ayrı bir approval gate olarak işaretle.

Implementation yapma.
File değiştirme.
Test/build çalıştırma.
Git işlemi yapma.
```

### What to Observe

- change surface sınırlı mı?
- temporary production mutation öneriliyor mu?
- dependency change ayrı gate mi?
- Git/remote mutations dışarıda mı?

## D01-M02-P03 — Plan Revision

Bu adımı yalnızca plan gereksiz risk/scope expansion içeriyorsa kullanın.

```text
Planı revise et.

1. @Valid'i temporary olarak kaldırma önerisini çıkar.
2. Null / empty / whitespace / missing validation scenario'larını netleştir.
3. Invalid request'lerde service'in çağrılmadığını doğrulama stratejisini koru.
4. Test infrastructure eksikse pom.xml değişikliğini ayrı approval gate yap.
5. Production, Git ve remote mutation'ları bu planın implementation scope'undan çıkar.
6. Yalnızca gerekli approval gate'leri bırak.

Henüz implementation yapma.
```

## D01-M02-P04 — Stop at Approval Gate

```text
Plan planning artifact olarak kabul edildi.

Ancak execution approval vermiyorum.

Implementation başlatma.
File değiştirme.
Test/build çalıştırma.
Git işlemi yapma.

Human approval gate'i raporla ve dur.
```

### Discussion Point

> **PLAN READY ≠ EXECUTION APPROVED**

## Module Takeaway

```text
Mode
→ interaction/delegation level

Permission

Approval

```
