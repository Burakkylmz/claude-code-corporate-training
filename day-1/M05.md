# M05 — Token, Context & Performance Management

## Learning Goal

Context composition, usage/cost, compaction, clear ve model-selection kararlarını ölçülebilir şekilde gözlemlemek.

## Performance Mental Model

```text
Scope
→ Context
→ Tools
→ Model / Effort
→ Verification
```

## D01-M05-S01 — Observe Context

Do **not** clear first.

Run:

```text
/context
```

### What to Observe

- total context usage
- Messages
- System tools
- Skills
- Memory files
- free space
- autocompact buffer

### Discussion Point

> **Context Window ≠ user prompts only**

## D01-M05-S02 — Observe Usage

Run:

```text
/usage
```

### What to Observe

- session cost
- API duration vs wall duration
- plan/session limit usage
- prompt cache
- subagent-heavy usage indicators
- high-context usage indicators

### Discussion Point

```text
/context
→ working context composition

/usage
→ resource / quota / cost consumption
```

Therefore:

```text
context %
≠
usage %
```

## D01-M05-S03 — Compact Experiment

Note the current `/context` values, then run:

```text
/compact
```

Immediately after:

```text
/context
```

### What to Observe

- total context decreases
- Messages footprint decreases significantly
- system/tool baseline largely remains

### Discussion Point

```text
/compact
→ same goal
→ summarize conversation
→ continue
```

> **Compression ≠ lossless storage**

## D01-M05-S04 — Clear Experiment

Run:

```text
/clear
```

Then:

```text
/context
```

### What to Observe

- Messages near-empty
- system/tools/skills still consume baseline context
- `/clear` does not mean 0-token context

Then run:

```text
/usage
```

### Discussion Point

> **`/clear` does not refund consumed usage.**

## D01-M05-P01 — Model Selection Before Execution

### Prompt

```text
Performance optimization analysis:

Task:

"CallOrchestrationService sınıfını incele ve mevcut orchestration
flow'unu 5-8 maddelik technical summary olarak açıkla."

Henüz task'ı execute etme.

Önce sınıflandır:

1. Scope complexity
2. Context requirement
3. Tool requirement
4. Reasoning difficulty
5. Expected verification cost

Sonra değerlendir:

- Sonnet 5 yeterli mi?
- Opus 5.5 escalation gerekli mi?
- Hangi durumda model escalation over-provisioning olur?
- Model değiştirmeden önce hangi değişkenler optimize edilmeli?

Başlıklar:

- Task Classification
- Minimum Required Context
- Required Tools
- Model Recommendation
- Why Not Escalate Yet
- Escalation Triggers

Henüz file okuma.
Tool kullanma.
Implementation yapma.
```

### What to Observe

```text
small scope
+ small context
+ low ambiguity
+ low verification cost
→ Sonnet 5
```

### Discussion Point

> **Model upgrade is not the first optimization lever.**

## D01-M05-P02 — Focused Execution

### Prompt

```text
Execution strategy onaylandı.

Şimdi task'ı uygula.

Goal:
CallOrchestrationService içindeki mevcut orchestration flow'u
5-8 maddelik technical summary olarak açıkla.

ALLOWED:
- CallOrchestrationService.java dosyasını oku.
- Gerçekten gerekirse doğrudan kullanılan gateway interface'lerinin
  yalnız method signature'larını oku.

NOT ALLOWED:
- Concrete adapter'ları okuma.
- Tests okuma.
- Config okuma.
- Broad repository scan.
- File değiştirme.
- Build/test.
- Git.
- Network.
- Subagent.

Task sonunda:
- kaç file okuduğunu,
- hangi tool türlerini kullandığını

raporla ve dur.
```

### What to Observe

A well-scoped run should:

- read only minimum source context,
- avoid subagents,
- avoid build/test,
- avoid writes,
- stop once evidence is sufficient.

Then run:

```text
/context
```

Compare against the fresh baseline.

### Discussion Point

> **1 file read ≠ only that file's tokens**

Context can also include:

```text
prompt
tool call
tool result
file content
assistant response
```

## Model Escalation Rule

Routine work:

```text
repository discovery
bounded implementation
read / summarize
ordinary tests
normal debugging

→ Sonnet 5
```

Consider escalation when:

```text
high ambiguity
+ cross-cutting architecture
+ difficult root-cause analysis
+ large trade-off space
+ high verification risk

→ Consider Opus 5.5
```

But:

```text
Large context alone
≠
Opus required

Security-sensitive task
≠
Opus required
```

## Module Takeaway

```text
/context → What is occupying working context?
/usage   → What am I consuming?
/compact → Same goal, smaller working history.
/clear   → New cohesive goal, reset conversation boundary.
```
