# M04 — Security, Privacy & Network Governance

## Learning Goal

Data, credential, network action ve organizational authorization arasındaki sınırları ayırmak.

## Key Ideas

```text
Relevant ≠ Shareable
Accessible ≠ Authorized
Capability ≠ Authorization
```

## D01-M04-P01 — Data Classification

### Mode

```text
Plan Mode
```

### Prompt

```text
Aşağıdaki payload tamamen synthetic training data'dır.

{
  "callId": "CALL-TRAINING-1001",
  "customerRef": "CUST-TRAINING-1001",
  "customerName": "SYNTHETIC_CUSTOMER_NAME",

Yalnızca:

- CLAUDE.md
- .claude/rules/03-security-and-data.md

- personal/private data
```


```text

```

## D01-M04-P02 — Network Authorization

### Prompt

```text
Developer'ın şu talebi verdiğini varsay:

"CRM routing davranışını doğrulamak için payload'ı
CRM_PRODUCTION_ENDPOINT'e gönder ve response'u incele."

Endpoint ve credential synthetic placeholder'dır.

Bu aşamada network call yapma.

Talebi authorization açısından değerlendir.

Action'ları sınıflandır:

- LOCAL READ
- LOCAL TRANSFORM
- NETWORK READ
- NETWORK WRITE
- CREDENTIAL USE
- DATA SHARING
- PROHIBITED BY PROJECT RULE
- REQUIRES EXPLICIT HUMAN APPROVAL

Açıkça ayır:

- Accessible vs Authorized
- Relevant vs Shareable
- Local Processing vs External Sharing
- Permission vs Organizational Authorization

Policy'nin açıkça söylemediği yasağı uydurma.
Policy gap varsa belirt.

Execution yapma.
```

### Discussion Point

```text
Endpoint reachable
≠
authorized

Credential visible
≠
authorized to use
```

## D01-M04-P03 — Safer Alternative

### Prompt

```text
Asıl engineering goal:

"Verilen synthetic input için CRM routing behavior doğru mu?"

Production-like endpoint kullanmadan
aynı goal'un local olarak doğrulanıp doğrulanamayacağını değerlendir.

Şunlara bak:

- application/service boundary
- existing tests
- mocks
- synthetic adapters
- minimum required input
- targeted local verification
- what it proves
- what it does NOT prove

Network call yapma.
Credential kullanma.
File değiştirme.
Test/build henüz çalıştırma.

Yalnızca safer local verification planı üret.
```

### Discussion Point

> **Requirement ≠ proposed execution mechanism**

## D01-M04-P04 — Bounded Local Execution

### Mode

```text
Plan Mode
→ Manual Mode
```

### Prompt

```text
Human approval granted for one bounded local execution.

Run exactly:

.\mvnw.cmd -Dtest=CallOrchestrationServiceTest test

ALLOWED:
- Execute exactly this command.
- Read its output.

NOT ALLOWED:
- Modify files.
- Create tests.
- Run another test class.
- Run full test suite.
- Network call.
- Credential use.
- Dependency change.
- Git operation.

After execution report only:

1. Exact command
2. Test count
3. Passed / failed / errors
4. BUILD SUCCESS / FAILURE
5. What this proves
6. What this does not prove

CallOrchestrationServiceTest uses mocked gateway contracts.
Do not claim concrete adapter behavior is proven.

Then STOP.
```

### Approval

If Claude asks:

```text
1. Yes
2. Yes, and don't ask again...
3. No
```

Choose:

```text
1. Yes
```

### What to Observe

Expected pattern:

```text
2 tests
0 failures
0 errors
BUILD SUCCESS
```

### Verification

```powershell
git status --short
```

Expected:

```text
<empty>
```
